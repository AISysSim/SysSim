# Task 4 - Low-Precision Support Tutorial

## Overview

This tutorial shows one example of how SysSim supports training-performance
prediction with low-precision acceleration. The example compares FP16 roofline,
FP8 roofline, and FP8 profiling-model predictions for:

- Model: `Qwen/Qwen3.5-9B`
- Batch size: `2`
- Sequence length: `1024`
- Hardware: `1 x H100`
- Training-step scope: forward + backward

Current SysSim training traces cover the forward pass, loss, and backward pass.
SysSim does not trace the optimizer update yet, so this tutorial does not include
optimizer-update time or optimizer-update memory. Model-state memory numbers below
therefore report parameter and gradient state only. AdamW optimizer states and
FP32 master weights are intentionally excluded.

## Use the Roofline Model

The roofline model is the fastest and simplest SysSim path. It traces the model
with fake CUDA tensors and computes an analytical performance ceiling from the
operator shapes and hardware limits. It does not allocate or execute real model
weights, and it does not run real GPU kernels for the model step.

For FP8, the H100 roofline config uses FP8 tensor-core throughput for GEMM and
attention compute FLOPs:

```python
from syssim import HardwareInfo


def h100_fp16_config():
    return HardwareInfo(
        peak_tflops_mm=1979.0,
        peak_tflops_math=989.0,
        peak_memory_bandwidth_gbps=3350.0,
        peak_tflops_mm_conservative=535.0,
        peak_tflops_mm_fp8=3958.0,
    )


def h100_fp8_roofline_config():
    return HardwareInfo(
        peak_tflops_mm=3958.0,
        peak_tflops_math=989.0,
        peak_memory_bandwidth_gbps=3350.0,
        peak_tflops_mm_conservative=1070.0,
        peak_tflops_mm_fp8=3958.0,
    )
```

Run the tracked roofline script from the SysSim repo root:

```bash
python docs/tasks/scripts/low_precision_roofline_h100.py \
    --model-scale full \
    --batch-size 2 \
    --seq-len 1024
```

The script writes:

```text
docs/tasks/results/low_precision_roofline_h100.json
```

## Use the Profiling Model

The profiling-model path starts with the same roofline features, then applies a
learned efficiency model trained from measured FP8 GEMM and attention kernels.
This is slower to set up than roofline because it profiles representative
operator shapes and trains local XGBoost models, but it can capture hardware and
kernel efficiency effects that pure roofline does not model.

The checked-in result uses a small reduced profiling smoke grid:

```bash
python docs/tasks/scripts/low_precision_profile_model_h100.py \
    --model-scale full \
    --profile-scale reduced \
    --batch-size 2 \
    --seq-len 1024 \
    --num-runs 1
```

The script writes:

```text
data/profiling/gemm_h100_fp8_data.csv
data/profiling/attn_h100_fp8_data.csv
data/trained_models/gemm_h100_fp8_xgb.pth
data/trained_models/attn_h100_fp8_xgb.pth
docs/tasks/results/low_precision_profile_model_h100.json
```

The `data/trained_models/*.pth` files are generated local model artifacts and are
ignored by `.gitignore`.

## Expected Results

These are the expected results from the completed H100 run:

| Method | Predicted Wall Time (ms) | Operators Traced | Model-State Memory (GB) |
| --- | ---: | ---: | ---: |
| FP16 roofline | `107.3405` | `5608` | `32.8341` |
| FP8 roofline | `86.3610` | `5608` | `24.6256` |
| FP8 profiling model | `205.6625` | `5608` | `24.6256` |

The FP8 roofline estimate is lower than the FP16 roofline estimate because the
FP8 configuration uses H100 FP8 tensor-core peak throughput for tensor-core
operators and counts FP8 parameter bytes. The FP8 profiling-model estimate is
higher than the FP8 roofline estimate because the learned efficiency correction
accounts for measured kernel behavior.

The reduced profiling smoke run produced:

| Item | Result |
| --- | --- |
| Profile scale | `reduced` |
| Kernel runs per profile shape | `1` |
| FP8 GEMM profile rows | `12` rows, `12` valid, `0` invalid |
| FP8 attention profile rows | `12` rows, `12` valid, `0` invalid |
| GEMM model final time MAPE | `19.1333%` |
| Attention model final time MAPE | `52.8628%` |

Because the profiling dataset is intentionally tiny, treat the FP8 profiling
number as a tutorial workflow artifact rather than a production-quality
calibrated estimate. For a more stable profiling model, increase the profiling
grid and `--num-runs`.

## Notes and Limitations

- Current SysSim does not trace optimizer update kernels, so optimizer-update
  wall time and optimizer memory are not included.
- SysSim tracing requires CUDA because it uses fake CUDA tensors to dispatch
  through GPU operator paths.
- The measured model is Qwen3.5-9B-shaped, but this exact config under
  `transformers 5.9.0` instantiates `8,208,535,552` parameters.
- The roofline FP8 script is an analytical ceiling and will usually underpredict
  measured wall time.
- The checked-in profiling-model expected output uses a one-run reduced smoke
  grid. Increase `--profile-scale` and `--num-runs` for better calibration.
